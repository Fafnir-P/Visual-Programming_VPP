WIRING / REQUEST PROBLEMS FOUND (not fixed; prototype/, card_templates/, tests/ untouched)
 1. Enter Number (and the other Enter/Toggle/Slider cards) take their value from an optional input "value" or from a UI
    event. In a graph with nothing linked there, the generator has no source for the numbers. I had to invent a
    USER_ENTRIES dict in main.py (marked GAP in a comment). The prompt says do not guess/invent; the request has no
    setting such as "default value", so this cannot be solved from the request.
 2. The request does not say how to call a template. Every function takes ctx first, but the prompt never explains
    Context / Store, the module path (card_templates.runtime), or how to read outputs (dict keyed by output port id).
    I used Context(store=Store()) from reading runtime.py. A real model without repo access would guess.
 3. Python version: SYSTEM_PROMPT says "Target Python 3.8+", but templateCode uses 'float | None' (Validate Number
    Range signature), which needs Python 3.10+ at def time (the module's 'from __future__ import annotations' is lost
    when only the function source is exported). Ran here on 3.13 only; not tested on 3.8.
 4. SYSTEM_PROMPT still says "template code placeholder" under "Each card has" (stale wording; tests check a different
    phrase so they miss it).
 5. Output format is vague: prompt asks for a "list of files and content" but not a machine-readable format, so the
    app cannot reliably split the reply into files. Also nothing says what the program should print at the end
    (I printed the banner view JSON and RESULT: line myself).
 6. Bloat: the same Enter Number source (512 B) is sent twice; both nodes carry identical config (name 'number'),
    so two cards would produce the same field id. Each node also repeats keys like catalogID, category. 10.3 KB for 8
    cards is about 1.3 KB per card; fine at this size.
 7. Control links: implicit _start/_done ports are not sent; order alone carries sequence. Worked here, but App End.finish
    must be linked (I linked App Start.event -> App End.finish); the prompt does not say what "finish" means.
 8. Harness note (not an app defect): nodes without 'role' make findGenerationIssues report no_start/no_end; tests/
    request.test.js nodes omit role too, so they never cover it.

OVERALL: PARTIAL. The request path works and a small program was built and ran, but only after the generator filled
gaps 1-3 by hand. Not checked: Python 3.8/3.9, real model output, response parsing in the app.
